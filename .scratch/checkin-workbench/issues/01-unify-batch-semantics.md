# 01：统一批量签到业务语义

**要构建的内容：**

让现有批量签到入口使用统一的批量签到规则和结果语义。管理员选择多个签到账号后，服务端统一判断哪些账号可执行、哪些账号需要跳过，并返回可解释的批量汇总；单账号签到继续保持独立行为，已有同步调用方继续兼容。

**阻塞于：** 无（可以立即开始）

Type: task
Status: resolved

- [x] 批量签到使用统一的批量触发来源，不再把一次批量操作伪装成多次单账号手动签到。
- [x] 服务端最终执行跳过规则：今日已签到、已停用、关闭重试、达到每日尝试上限的账号被跳过，并返回跳过原因。
- [x] 每个实际执行账号产生独立签到记录；今日已签到归入已完成但不计为本次新成功。
- [x] 批量汇总包含总数、成功数、失败数和跳过数，前端能展示逐账号结果和可读错误。
- [x] 单账号签到行为和已有同步批量调用方保持兼容。
- [x] 为上述外部行为补充后端和前端测试，不依赖真实外部站点。

## Answer

批量签到统一使用 `manual_batch` 触发来源，服务端统一执行今日已签到、停用、重试开关和每日尝试次数判断；实际执行写入独立签到记录，跳过项保留在批次范围中。批次汇总和逐账号状态由工作台展示，旧的同步批量接口继续保留。
