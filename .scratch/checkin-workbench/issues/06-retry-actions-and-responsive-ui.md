# 06：失败处理、快捷操作与响应式 UI

**要构建的内容：**

完成签到工作台的操作闭环和视觉收尾：管理员可以直接处理失败账号和常用账号操作，桌面端与移动端都能完成核心流程，界面在加载、空数据、错误、暗色主题和键盘操作下保持清晰可用。

Blocked by: 05

Type: task
Status: resolved

- [x] 支持单个可重试失败账号重试，重试产生新的签到记录，不覆盖原始失败记录。
- [x] 支持从批次详情或失败列表批量重试，只纳入可重试失败，并展示确认范围和结果。
- [x] 账号列表行提供单账号签到、刷新余额、编辑和查看记录；启用、停用、删除等影响性操作需要确认。
- [x] 批量操作有明确的开始、进行中、完成、失败和部分成功反馈，不使用页面离开来模拟停止。
- [x] 桌面端使用可排序、可选择的数据表格；移动端切换为账号卡片并保留固定批量操作入口。
- [x] 提供骨架屏、首次使用引导、无匹配结果、网络错误、权限不足和脱敏错误详情。
- [x] 明暗主题下保持一致的状态颜色、数字层级、间距和对比度；状态颜色不混淆签到状态与余额预警。
- [x] 所有核心控件具有可见焦点样式和键盘操作路径，并遵循 `prefers-reduced-motion`。
- [x] 使用 180–240ms 的克制过渡，不使用依赖复杂动画才能理解的反馈。
- [x] 通过前端测试、生产构建和人工浏览器验收确认桌面/移动布局、暗色主题、键盘可用性和减少动效行为。

## Answer

工作台支持单账号和批量失败重试，重试继续走异步批次并生成新的签到记录；仅纳入启用且允许重试的失败项。桌面端使用可选择表格，移动端使用账号卡片和固定操作条；界面提供骨架屏、空状态、错误状态、暗色主题、焦点样式和减少动效适配。
