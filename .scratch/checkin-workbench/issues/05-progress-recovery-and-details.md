# 05：实现进度恢复、批次详情与结果导航

**要构建的内容：**

让管理员持续掌握签到批次进度，并在刷新、离开页面或 Cloudflare/浏览器短暂断线后恢复查看。工作台需要提供批次汇总、逐账号状态、可读失败原因和到签到记录的上下文跳转；批次启动后不因页面离开而停止。

Blocked by: 04

Type: task
Status: resolved

- [x] 执行中的批次按约定周期轮询，展示总数、完成数、成功数、失败数和跳过数。
- [x] 批次整体状态正确显示为执行中、已完成、部分失败或全部失败。
- [x] 逐账号显示成功、今日已签到、失败、跳过和执行中状态，并展示可读且已脱敏的错误信息。
- [x] 批次详情通过侧边抽屉或可展开区域打开，不丢失工作台当前筛选和批次上下文。
- [x] 刷新页面、离开后返回或 Cloudflare 连接恢复时，能够凭批次编号继续轮询，不重新创建批次。
- [x] 批次终态后停止轮询，并保留手动刷新入口；状态查询不能依赖代理缓存。
- [x] 批次启动后离开页面不会停止服务端执行；不提供取消或暂停按钮，仅对停滞批次提供明确的手动重新入队入口。
- [x] 批次详情可跳转到签到记录页面，并自动带入对应批次或失败结果筛选。
- [x] 覆盖轮询、断线重连、部分失败、全部失败、终态停止轮询和权限隔离的前端模拟 API 测试。

## Answer

工作台按固定间隔只轮询执行中的批次，终态后停止轮询；浏览器刷新或短暂断线时从本地保存的批次编号恢复查询，不会重新创建。详情抽屉展示批次汇总、范围快照、逐账号状态和脱敏错误，并可带 `batchId` 跳转签到记录。另提供明确的“重新入队”入口处理停留在等待状态的批次。
