# 02：实现 Cloudflare 安全的异步签到批次

**要构建的内容：**

让工作台可以创建一个不会被 Cloudflare 长请求超时影响的签到批次。创建请求只完成授权、范围校验、签到范围保存和任务入队，快速返回批次编号；服务端在后台继续执行，并提供可查询的批次生命周期和逐账号进度。网络重试不能重复创建批次。

Blocked by: 01

Type: task
Status: resolved

- [x] 创建异步签到批次时，在外部站点执行完成前就返回批次编号，不让浏览器请求等待整批签到。
- [x] 批次持久化签到范围、触发来源、批次状态、批次汇总和逐账号执行结果关联。
- [x] 提供批次状态查询，至少支持执行中、已完成、部分失败和全部失败，并返回总数、完成数、成功数、失败数和跳过数。
- [x] 批次状态响应声明禁止缓存，避免 Cloudflare 返回旧进度。
- [x] 创建请求支持客户端幂等标识；相同标识重复提交时返回原批次，不创建重复批次。
- [x] 服务端后台串行执行批次；单个站点请求超时只生成可重试失败，后续账号仍继续执行。
- [x] 浏览器或 Cloudflare 连接中断不影响批次；重新查询批次编号能够获得最新状态。
- [x] 工作台异步模式与旧同步批量调用并存，旧调用方的行为不被破坏。
- [x] 使用延迟站点执行替身测试创建快速返回、进度变化、幂等创建、禁止缓存、单账号超时后继续执行和权限隔离。

## Answer

签到批次已持久化到 `CheckinBatch` / `CheckinBatchItem`，创建接口只完成授权、范围快照和后台入队，状态查询与工作台聚合查询均返回 `no-store`。客户端支持请求体或 `Idempotency-Key` 幂等标识；后台按账号串行执行，单账号失败后继续后续账号。Cloudflare 断线只影响查询，不影响服务端批次。
